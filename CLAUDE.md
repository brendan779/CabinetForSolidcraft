# CabinetForSolidcraft: notes for Claude

A cabinet-making tool for the SolidCraft CAD app (tangency-labs/solidcraft). A Rust core turns
boxes into cabinets (panels, biscuit + screw joinery, Blum/Häfele hardware, cut lists, cut sheets).
A native SwiftUI macOS app ("Cabinet Studio") is the interface, and it drives a running SolidCraft
over its control socket. When SolidCraft ships its WASM plugin runtime, the core moves into a plugin.

- Plan of record: [docs/BACKLOG.md](docs/BACKLOG.md). Unattended work: [docs/OVERNIGHT.md](docs/OVERNIGHT.md).
- Background and decisions: [docs/FEASIBILITY_PLAN.md](docs/FEASIBILITY_PLAN.md).

## Layout

| Path | What |
|---|---|
| `crates/cabinet-core` | Domain model → `PartList` (parts, operations, hardware), joinery, cut list, option catalogue. No I/O |
| `crates/cabinet-catalog` | Board / edge tape (and later hardware) JSON schema, loader, validation |
| `crates/cabinet-sheets` | SVG cut sheets |
| `crates/solidcraft-bridge` | Control-protocol client + `PartList` → engine commands |
| `crates/cabinet-ffi` | UniFFI bindings for Swift |
| `apps/macos` | SwiftUI app. `project.yml` is the source; the `.xcodeproj` is generated by `xcodegen` |
| `catalog/` | Data files: `boards/`, `hardware/` (format in its README). Every record has a `source` |
| `vendor-cad/` | Supplier CAD, **local only, never committed** |

## Commands

```bash
scripts/check.sh               # the gate: fmt, clippy -D warnings, tests, app build
scripts/build-core.sh          # Rust → CabinetCore.xcframework + Swift bindings
cargo insta review             # accept changed golden part lists / cut sheet snapshots (cargo install cargo-insta)
cd apps/macos && xcodegen      # regenerate the Xcode project
cargo run -q -p solidcraft-bridge --example emit_base   # live build into the running SolidCraft
cargo run -q -p solidcraft-bridge --example emit_base -- --script target/run.json \
  && /Applications/SolidCraft.app/Contents/MacOS/solidcraft-cli run target/run.json --out target/run.step  # headless
```

Rust is installed through Homebrew's rustup: `export PATH="$HOME/.cargo/bin:/opt/homebrew/opt/rustup/bin:$PATH"`.

## Conventions

- Millimetres everywhere. Cabinet frame: X across the front, Y from the front face (0) to the back,
  Z up.
- Part names are `<cabinet id>.<Role><n>` and must stay stable across rebuilds.
- Supplier numbers (hinge boring distance, runner deductions...) live in catalog data with a
  source, never as unexplained literals. Existing constants in `build.rs` that say VERIFY are
  temporary.
- Tests describe behaviour in their names (`rails_are_screwed_not_biscuited`). Every new rule gets
  a test. A rule change also changes the golden part lists (`crates/cabinet-core/tests/snapshots`):
  review the diff, then accept it with `cargo insta review`.
- Comments explain why, briefly. Match the density of the file you're in.
- The UI is the product: every option is a picture, not a number field. Use system materials and
  controls, Liquid Glass on macOS 26 through `glassBackground()`, and animate changes with
  `.snappy`.

## macOS layout rules (each one crashed the app)

AppKit throws on layout loops and unsatisfiable constraints, and the app dies. Before committing
UI, launch the Release build under `lldb` with a breakpoint on `objc_exception_throw` and visit every
workspace, windowed and full screen (⌃⌘F). To stop that copy, kill `lldb` first and then the app:
signalling the app first is caught by the debugger, and the app outlives it.

- Don't add window toolbar items from workspace views; the toolbar is full. Put controls in a bar
  inside the view.
- No `HSplitView` inside the detail column next to the inspector.
- Window tabbing stays off (`NSWindow.allowsAutomaticWindowTabbing = false`).
- No AppKit `.sheet` over the job window; use the overlay pattern (see the welcome card).
- Split view columns must not take their min/max size from their content: the workspace area has
  `.frame(minWidth: 0, …)` and the inspector always has `inspectorColumnWidth`.
- Rows of fixed-size controls must fit 420 pt or be allowed to shrink.

## SolidCraft facts (checked 2026-10-23, v0.20.0)

- Control protocol: JSON lines on `127.0.0.1:7878`, token in
  `~/Library/Application Support/SolidCraft/control/7878.token`. Methods `engine.execute`,
  `engine.batch` (all-or-nothing, up to 10 000 steps), `document.inspect`.
- Useful commands: `solid.box` (corner, body_name, operation, targets), `solid.cylinder` (base,
  axis, diameter, height), `component.create/activate/delete`, `component.metadata.set` (values
  under a reverse-DNS key), `appearance.assign` (bodies, color), `sketch.create` (plane
  `{origin, x_dir, y_dir}`), `sketch.circle.center`, `solid.extrude` (sketch, profiles, direction,
  operation `cut`, targets). `solidcraft-cli commands` lists them all with their params.
- `component.list` gives each occurrence's `transform` as four columns (translation last);
  `occurrence.move` takes `matrix` as rows. A new component's placement is `<name>:1`.
- Every cut costs more the more features its body has: batch holes into one sketch extrude
  (docs/perf.md).
- SolidCraft 0.22 (2026-10-26) grounds a design's first part when it is made; a grounded
  occurrence refuses `occurrence.move`. Send `occurrence.ground {occurrence, grounded: false}`
  first (works on 0.20 too). This Mac runs 0.22; MacAirServer and CI test with the 0.20 CLI.
- Preferences › Plugins only lists folders. No plugin code runs yet (issue #1221, draft PR #4980).
